# Настройки

Основные настройки задаются через .NET user secrets или переменные окружения.
Переменные окружения имеют приоритет.

| Переменная | По умолчанию | Для чего |
| --- | --- | --- |
| `Bot__Token` | — | Токен бота |
| `Bot__AdminUserId` | — | Числовой ID администратора |
| `Bot__DatabasePath` | `data/tgbroadcast.db` | Путь к SQLite |
| `Bot__SendIntervalMilliseconds` | `100` | Пауза между отправками, минимум 50 мс |
| `Bot__MaxDeliveryAttempts` | `5` | Число попыток, от 1 до 20 |
| `Bot__MediaGroupDelayMilliseconds` | `1500` | Пауза для сбора альбома, от 500 до 10 000 мс |
| `Bot__DraftLifetimeHours` | `24` | Срок подтверждения черновика, от 1 до 168 часов |

Путь к базе считается от текущей рабочей папки.
Файл `.env` используется только Docker Compose. При запуске через `dotnet run` он не читается.

## Импорт из Python-версии

Подписчики импортируются из JSON-массива положительных числовых ID.
Дубликаты удаляются, существующие подписчики активируются повторно.

```bash
dotnet run --project src/TgBroadcast -- --import-subscribers /path/to/subscribers.json
```

Создать базу без запуска бота:

```bash
dotnet run --project src/TgBroadcast -- --init-db
```

Обе команды работают без токена и не обращаются к Telegram.
Python-версия сохранена в истории Git. Рабочие базы и файлы с подписчиками в репозиторий не добавляются.

## Миграции

Миграции применяются при запуске приложения.
Проверить, что модель соответствует последней миграции:

```bash
dotnet tool restore
dotnet ef migrations has-pending-model-changes --project src/TgBroadcast
```

## Особенности отправки

- Рассылку может подтвердить только администратор в личном чате.
- Список получателей фиксируется при подтверждении. Отписавшиеся до отправки пропускаются.
- Альбом собирается после паузы между сообщениями. После подтверждения добавить в него новые части нельзя.
- Опросы пересылаются, остальные сообщения копируются.
- После сбоя между отправкой и записью результата в базу последняя доставка может повториться.
- Частично скопированный альбом считается неудачной доставкой и целиком автоматически не повторяется.

Перед переходом с Python нужно остановить старого бота. Для long polling у бота не должно быть активного webhook.
Перед открытием репозитория нужно удалить старый токен из истории Git.
